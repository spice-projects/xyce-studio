# Xyce Netlist Lexer Specification

This document summarizes the lexical rules and syntax constraints supported by [`NetlistLexer`](netlist_lexer.h), validated against the **Xyce Reference Guide Release 7.10** (`xyce-docs/Xyce_RG.txt`).

## Specification & Lexical Rules Comparison

| Category | Xyce Reference Guide Rule | Netlist Lexer Implementation | Classification |
| :--- | :--- | :--- | :--- |
| **Full-line Comments** (§2.1.39) | Line beginning with `*` as first non-whitespace character. | Lines starting with `*` (ignoring leading whitespace) are consumed until `\n` or `\r\n`. | `NetlistTokenType::COMMENT` |
| **In-line Comments** (§2.1.39) | In-line comments start with `;` anywhere on a line. | Semicolon `;` outside string literals or expressions consumes the rest of the line. | `NetlistTokenType::COMMENT` |
| **HSPICE `$` Divergence** (§2.1.39, §2.3.1.1) | In standard HSPICE, `$` begins an in-line comment. In **Xyce**, `$` is **NOT** a comment; `$G...` denotes **Global Nodes** (e.g. `$G_VDD`, `$G_GlobalNode1`). | The lexer strictly avoids treating `$` as a comment; words starting with `$G` or `$g` are classified as nodes. | `NetlistTokenType::NODE` |
| **Line Continuations** (§2.1.39) | A line beginning with `+` as the first non-whitespace character is a continuation line. | Any line starting with `+` after whitespace emits `+` as continuation operator, preserving context. | `NetlistTokenType::CONTINUATION` |
| **Directives & Commands** (§2.1) | Commands begin with `.`, such as `.TRAN`, `.AC`, `.DC`, `.HB`, `.OP`, `.MODEL`, `.SUBCKT`, `.ENDS`, `.PREPROCESS`, `.PRINT`, `.PROBE`, `.MEASURE`, `.GLOBAL`, `.OPTIONS`, `.DATA`, `.RESTART`, `.STEP`, `.SAVE`, `.SENS`, `.SAMPLING`. | Scans `.` followed by alpha characters (excluding decimal numbers like `.5`), extracting the directive name. | `NetlistTokenType::DIRECTIVE` |
| **Scale Multipliers** (§2.2.1) | SPICE engineering scale suffixes: `T` ($10^{12}$), `G` ($10^9$), `MEG` ($10^6$), `K` ($10^3$), `MIL` ($25.4\mu\text{m}$), `M` ($10^{-3}$), `U` ($10^{-6}$), `N` ($10^{-9}$), `P` ($10^{-12}$), `F` ($10^{-15}$). | Tokenizer extracts numbers followed by scale multipliers (e.g., `10u`, `100k`, `1e-6`, `25MEG`, `10mH`, `1uF`). | `NetlistTokenType::NUMBER` |
| **Complex Numbers** (§2.2.1) | Complex values can use the imaginary suffix `J` / `j` (e.g., `2.0J`, `1.0+2.0J`). | Numbers with trailing `j` or `J` are recognized as complex numeric literals. | `NetlistTokenType::NUMBER` |
| **Expressions** (§2.2) | Expressions are enclosed in curly braces `{...}` or single quotes `'...'`. | Full `{...}` spans are captured as expressions, including nested operators and unclosed expressions; single-quoted spans are captured as string literals. | `NetlistTokenType::EXPRESSION` / `NetlistTokenType::STRING_LITERAL` |
| **Expression Operators** (Table 2-32) | Exponentiation `**`, relational `==`, `!=`, `<`, `<=`, `>`, `>=`, logical `~`, `\|`, `&`, `^`, conditional `? :`, arithmetic `+`, `-`, `*`, `/`. | Multi-character operators `**`, `==`, `!=`, `<=`, `>=` and single-character operators are tokenized. | `NetlistTokenType::OPERATOR` |
| **Built-in Functions** (Table 2-33 & 2-34) | Math: `ABS`, `SQRT`, `EXP`, `LN`, `LOG`, `LOG10`, `SIN`, `COS`, `TAN`, `ASIN`, `ACOS`, `ATAN`, `ATAN2`, `SINH`, `COSH`, `TANH`, `URAMP`, `LIMIT`, `IF`, `TABLE`, `AKIMA`, `CUBIC`, `FASTTABLE`, `POLY`.<br>Generators: `SPICE_PULSE`, `SPICE_SIN`, `SPICE_EXP`, `SPICE_SFFM`, `PWL`. | Case-insensitive lookup against the comprehensive keyword set (120+ keywords and built-in functions). | `NetlistTokenType::KEYWORD` |
| **Application Extensions** | Xyce implements no default-plot directive; `.PLOT` is listed as unsupported (RG Table 6-1). | `.PLOT` is an Xyce Studio extension declaring the default charts of a run and is highlighted like any other directive; the lexer only tokenizes it, `parse_netlist` lifts it out of the netlist body into `NetlistTopology::m_plot_directives` and the directive is re-inserted for the editor but never handed to the simulator. | `NetlistTokenType::DIRECTIVE` |
| **Device Primitives** (Table 2-35) | Device types: `R`, `C`, `L`, `K`, `D`, `Q`, `J`, `M`, `Z`, `B`, `V`, `I`, `E`, `F`, `G`, `H`, `T`, `U`, `O`, `W`, `S`, `X`, `P`. | Initial device token on each instance line is detected and associated with its expected pin count. | `NetlistTokenType::DEVICE` |
| **Xyce `Y` Devices** (Table 2-35) | Specialized `Y` devices: `YMEMRISTOR`, `YLIN`, `YACC`, `YPDE`. Xyce allows both single-token (`YMEMRISTOR1 ...`) and dual-token syntax (`YMEMRISTOR M1 ...`). | Both forms are supported: standalone `Y...` instances and `Y... <instance-name>` formats. | `NetlistTokenType::DEVICE` |
| **Node Names with `+` / `-`** (§2.3.2) | Differential and pin terminal names can terminate with `+` or `-` (e.g. `IN+`, `IN-`, `1+`, `1-`, `OUT+`). | Suffix `+`/`-` attached to alphanumeric words are preserved as part of the node name rather than split as operators. | `NetlistTokenType::NODE` |
| **Device Names with Hyphens** (§2.3.2) | Device instance names can contain embedded hyphens (e.g. `R-1`, `C-FB-1`). | Embedded hyphens flanked by alphanumeric characters are treated as identifier characters. | `NetlistTokenType::DEVICE` / `NODE` |
| **KiCad Net Names** | KiCad-generated netlists use net names with hyphens and underscores (e.g. `Net-_U303A-G2_`). | Hyphens followed by an alphanumeric character or underscore stay inside the identifier; the whole net name is one token. | `NetlistTokenType::NODE` |
| **Hierarchical Nodes** (§2.3.2) | Hierarchical pin references separated by `:` (e.g. `X1:IN`, `XTOP:XSUB:VOUT`). | Mid-word colons are tokenized as operators; a trailing colon before a word boundary stays inside the word (e.g. the `PARAMS:` keyword, §2.3.33). | `NetlistTokenType::OPERATOR` / `NODE` |
| **Subcircuit Instances** (§2.3.33) | Instance form `X<name> [node]* <subcircuit name> [PARAMS: [...]]`: the trailing token is the subcircuit name, not a node. | On X-instance lines the last non-comment token (or the token before `PARAMS:`) is reclassified as the model name; trailing parameter tokens fall back to keyword/number/plain classification. | `NetlistTokenType::MODEL` |
| **Ground Nodes** (§2.3.1.1) | Ground reference nodes: `0`, `GND`, `GROUND`. | Ground representations are mapped directly to nodes. | `NetlistTokenType::NODE` |
| **String Literals** | Quoted strings (e.g. `FILE="output.raw"` or `'netlist.cir'`). | Double-quoted and single-quoted strings and file paths are cleanly extracted. | `NetlistTokenType::STRING_LITERAL` |
| **Text Invariant Guarantee** | Formatting must preserve 100% of characters (spaces, tabs, `\r`, `\n`) for transparent Slint overlay alignment. | Concatenating `token.m_text` across all tokens plus each line's stored `m_line_ending` exactly reproduces the input document byte-for-byte. | Verified by unit tests |
